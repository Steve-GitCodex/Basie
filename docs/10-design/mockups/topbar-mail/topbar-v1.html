TOP BAR — v1 prototypes

Three responsive layouts for the header. Each one is drawn at desktop (1000), tablet (640) and phone (360) width. The frames use container queries, so you can also resize the browser window. Tap a resource to see its detail popover, and tap +N to see the hidden resources. Inputs: docs/research/topbar-mail-*.md. Click a card to select it.

Values: Late game shows the near-cap (amber) and full (red pulse) states.

OPTION A — One strip, priority overflow

The current single row, tidied up. Each chip shows only its value and a capacity line underneath. As the bar gets narrower, the lowest-priority resources move into a +N chip, so nothing is ever hidden in an invisible scroll again. The header stays 46px at every width.

Pros: smallest change. --header-height stays fixed, so the map, toasts and world view need no changes. Every existing #res-* id is kept.
Cons: on a phone you only see 2–3 resources at a glance. Moving the others into overflow needs a priority order, for example the resource you're short of comes first.
Phone: avatar · 2 chips · +3 · diamond · buff.

OPTION B — Two tiers on narrow screens · CHOSEN (ADR 0041)

Wide screens get one row: the player plate (name, level, power), then resources, premium currency and buffs. Below 700px it splits into a top row (player plate, currencies, buffs) and a row of five resource cells of equal width. All five resources stay visible on a phone.

Pros: everything stays visible at every width, with no overflow logic. The player name and power come back, since they're hidden today. Equal-width cells line up neatly.
Cons: the phone header is about 84px. --header-height needs to become responsive, and everything that uses it (toasts, world view, battle trail, map offset) has to follow.
Note: money moves to the top row next to diamond, so resources and premium currency read as two separate groups.

OPTION C — Commander plate (Last Shelter style)

The genre look: a large avatar on the left with an XP ring, a level hexagon and a power readout. The resource strip sits beside it. Below 560px the resources fold into a 3×2 grid, and diamond and buffs sit under the avatar.

Pros: the strongest grit-reskin identity. The avatar and power are always prominent, which gives a natural home for the level-up float and the VIP badge.
Cons: the most CSS work. The phone grid cells are tight, so values must stay at 4 characters or fewer, which compact formatting does. The header is about 76px on a phone, with the same token issue as B.
Note: the avatar overlaps the bottom edge of the header on purpose, as in the genre. The tutorial spotlight is not affected because no tutorial step targets the header.
